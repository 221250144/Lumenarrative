# 叙光集 Vlog 分析系统 v2

本次需求收窄：用户上传一条已经剪过的 Vlog，系统还原其内部镜头顺序，判断观众具体在哪一处缺少信息，再提出少量能执行的补拍或重剪建议。本文件描述当前实现，替代旧任务书中面向任意素材集合的主流程；历史项目和诊断仍可查看。

## 产品流程

**一条主 Vlog → 转场切分 → 逐镜头画面理解 → 全片上下文审阅 → 最多 5 条定位建议 → 人工确认 → 补拍视频分析 / AI 候选片段生成。** 最终剪辑由用户在其他软件完成。

首次上传自动指定主 Vlog。一个项目只有一条主片，之后的上传作为补充片段。替换主片需在界面明确选择；重新分析时只读选定主片，不把多个文件拼在一起猜故事。创作说明用于理解风格与意图，不会在看视频前自动扩展成一套必须完成的情节。

建议以“画面事实、理解障碍、修改动作”组成。例如，若前一镜头是准备食材，下一镜头直接出现装盘成品，模型需要先判断这种省略是否影响这条 Vlog 的实际表达。只有确实需要交代做法时，才建议在明确位置补一段具体操作近景；不能仅因为省略了过程就自动判为缺口。这个例子是产品规则说明，不是实际视频识别结果。

## 镜头与分析窗口分开

FFmpeg 对代理视频逐帧计算场景变化，检测硬切和经过黑场的淡入淡出候选。`scene_shots` 是覆盖整片、连续且不重叠的实际镜头候选：包含稳定 ID、序号、原片起止秒、切点类型、缩略图及关键帧。边界区间统一使用 `[start, end)`。

最短镜头为 0.5 秒：短段合并到相邻镜头，优先保留更强的画面切点，不裁掉视频时间。整片不足 0.5 秒时保留唯一镜头。历史诊断通过 `display_shots` 提供同样的合并展示，原始 `shots` 与证据锚点保持不变；详见[工作区细节调整](WORKSPACE_REFINEMENTS.md)。

每个镜头内部再建立供模型阅读的短窗口。长镜头可以包含多个重叠窗口，但在用户界面仍然只算一个镜头。每个窗口最多 4 张真实解码时间戳的关键帧，不跨转场；短于一秒的镜头同样抽取其内部画面。镜头不会被物理裁剪成一堆新文件，播放器通过原片时间区间定位并在片段结尾暂停，原始视频保留。

旧素材在新 Vlog 分析时依据 `SEGMENTATION_VERSION` 自动重新预处理。抽帧文件按配置集合隔离，历史快照不因新采样覆盖而指向错误图片。

## 两阶段模型理解

镜头理解已改为最多 8 路并发；线程只读素材快照，按完成数量更新进度，最终按原片顺序汇总。服务器用共享限额控制全部 worker 的模型请求与 FFmpeg 任务，详见 [8 核并发设计](CONCURRENCY.md)。

1. **镜头观察**：千问视觉模型读取采样帧和源时间，每窗口只写 1–2 条具体事实：谁、哪里、做什么、状态如何变化。看不清时写不确定，禁止直接在此阶段提补拍方案。服务端校验源时间并绑定真实镜头 ID。
2. **全片审阅**：文本模型读取原片顺序的镜头、观察事实、创作说明与覆盖情况，返回内容摘要、最多 6 个段落和最多 5 条值得改的建议。允许零条建议。普通跳切、日常蒙太奇、缺少标准开头/结尾都不自动构成问题。

建议类型为场景交代不足、动作交代不足、结果交代不足、衔接理解障碍、内容重复。每条都包含短标题、观察事实、观众缺少的具体信息、理解影响、锚点镜头、可选关联镜头、置信度与一个推荐动作。优先检查能否用片内已有画面删减或挪动解决；需要补拍时给出主体动作、景别、秒数、锚点前/后插入位置与 1–3 个验收条件。

模型引用经过独立验证：镜头、素材、证据 ID、镜头归属、源时间必须一致。每条建议只保留最多两段关键证据，优先锚点与关联镜头各一段；同镜头或重叠区间去重。已检索范围只用于覆盖说明，不会展开成一长串“证据视频”。旧诊断也限制为最多两段展示引用。

## 补拍、验收与重剪

新 Vlog 计划沿用建议里的具体操作，不再为每个问题机械生成三种泛泛方案。需要确认的意见不会自动选入执行计划。补充片段可提交到任务，按原验收条件检查新证据及连续性；仅上传成功不会判为补全成功。片段验收通过也不等于新素材已被插入主片，仍需实际重剪并审阅更新的 Vlog。

系统只提出重剪建议，不编辑时间线、不管理成片版本，也不导出成片或 EDL。用户可复制建议，在外部剪辑软件中完成调整。补拍任务支持上传实拍视频并逐项分析，或使用 HappyHorse 生成可预览、下载的 AI 候选素材；两者均不会自动插入主片。

此前的剪辑创建、版本列表/详情与成片/EDL 下载接口统一返回 410，旧渲染作业不能重试。历史数据库和媒体不删除，内部旧 worker 代码保留，确保发布前的已有作业可以正常收尾。

界面只保留项目、Vlog 审看、补拍与重剪建议三页。全局进度和错误放入“任务与消息”浮层，移除顶部常驻横幅；操作受阻原因放在对应按钮旁。主黄色为 `#D8BC3C`，保持原有视频与素材固定、镜头与建议独立滚动的工作区。

|具体任务与预算|`backend/app/services/planning/engine.py`|
|前端工作台、建议、分镜播放|`frontend/src/pages/Workbench.tsx`、`frontend/src/components/VideoPlayer.tsx`|

API 新建项目默认 `input_mode=vlog`，保留旧模式以兼容历史数据。Asset 返回 `shots`、`shot_count`、`segmentation_version`；Diagnosis 返回 `vlog` 摘要与章节、带观察摘要的 `shots`、已有 `evidence/requirements/matches/gaps`。Gap 增加 `anchor/recommendation/impact/issue_key`。沿用现有 JSON 存储和任务表，无需破坏性数据库迁移。

分析固定主片选择、素材快照、项目 revision 和模型/提示词/分镜版本。缓存只复用相同素材与配置的视觉事实；全片建议重新生成。过期分析只写历史，不覆盖当前版本。确认与忽略按“素材 + 稳定镜头 + 问题类型”记录，后续分析不会因措辞变化轻易丢失人工判断。

## 已知边界

- 切点是算法候选。复杂叠化、快速摇镜、闪光可能漏检或误分；当前没有手动合并/拆分镜头编辑器，也不宣称恢复原始剪辑工程。
- 关键帧理解不是逐帧动作识别。分析失败区间及低置信意见明确标记；没有建议不能解读成全片已被证明完美。
- ASR 未配置时只分析画面，不编造对白。依赖旁白才能判断的意见降为不确定，不能断言声音信息缺失。兼容 ASR 接口仍需单独配置。
- 演示模式只执行真实分镜处理，普通上传不伪造内容理解或补拍结论。合成视频测试能验证切点和链路，不能证明实拍 Vlog 的语义准确率。
- 本次仍使用团队已指定的 HTTP 免登录入口；部署不会改变此前的访问方式。
