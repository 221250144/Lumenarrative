# 叙光集 v0.1 实施说明

## 对任务书的落地选择

- 采用 React + TypeScript / FastAPI / SQLAlchemy 模块化单体；保持统一 API 与领域模型。
- 交付 PostgreSQL + Redis + Celery + FFmpeg 的 Compose 结构。由于当前机器没有 Docker，本地开发与验证使用 SQLite + 单 worker 线程，避免因基础设施缺失阻塞实际媒体链路。
- 以最新 PDF 的独立平台定位为准；影石 SDK 为可选扩展，未编造设备或远程接口。
- 名称采用用户消息中的“叙光集”，保留 PDF 的英文名 Lumenarrative；原始提案和架构文件不改写。
- VLM 使用时间标签 + Base64 抽帧，通过可配置的千问兼容协议请求。ASR 独立配置，失败会降低音频覆盖状态。
- 需求与证据先匹配，再生成候选缺口；默认人工复核。计划权重 3/2/1，边际覆盖按缺口去重；不输出虚构货币成本。
- 暂时采用保守基础时间线和直切渲染。任务验收通过与全项目无缺口分开显示，验证后需重新诊断。

## 数据保护与可靠性

- API 默认回环地址；没有外部 URL 导入。
- 服务端 UUID 文件路径、FFprobe 实际格式检查、上传数量/时长/大小限制、原片保留。
- FFmpeg 使用参数数组，不执行模型生成命令；允许协议限制为本地文件与管道。
- 模型输出通过 Pydantic 与引用/时间边界校验，前端使用 React 文本渲染。
- 上传、分析、补全提交支持幂等键。作业状态写入数据库，SSE 返回阶段和真实数量。
- 分析快照绑定项目 revision；修改后旧结果作为历史保留，不覆盖当前分析指针。
- Provider/模型/提示词/采样配置进入缓存键，缓存限定在项目和素材内；配置变化要求重新分析。
- `.env`、媒体、虚拟环境、构建目录不进入 Git；比赛个人信息不复制到本代码目录。
