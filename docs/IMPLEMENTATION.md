# 叙光集实施说明

本文件说明当前 `main` 的实现边界。项目由 NJU人型token队开发，产品名为“叙光集”，英文名为 Lumenarrative。历史任务书中的原始素材组片、粗剪版本和成片导出不再是当前产品能力。

## 当前产品流程

**登录 → 创建项目 → 上传一条已剪 Vlog → 镜头切分与分析 → 确认具体建议 → 补拍清单 → 上传补充视频复核或生成 AI 候选片段。**

- 输入是已有剪辑的视频，可含实拍或 AI 生成内容；新建项目默认单主片 Vlog 模式。分析关注画面表达与衔接，不把视频来源当成内容真实性的证明。
- 镜头边界由 FFmpeg 检测；不足 0.5 秒的短段合并到相邻镜头。系统保留原片，通过时间范围回看，不能还原原剪辑工程。
- 逐镜头理解与全片审阅分开执行，最多输出 5 条具体建议，每条最多展示 2 段关键证据。人工确认后再生成建议清单。
- 重剪只提供位置和操作建议；补拍只提供拍摄要求与验收条件。实拍补充片段和 AI 候选片段均可按任务复核；生成、上传成功不等于满足要求。
- HappyHorse 已合入 `main`。生成片段可预览、下载，交由用户在外部剪辑软件使用；系统不提供时间线编辑、成片版本管理、成片导出或 EDL 导出。旧相关公开接口返回 410，兼容数据和内部收尾代码仍保留。
- 用户名/密码账号提供项目隔离；项目支持重命名和软删除。删除不会立即物理清除底层媒体，详见 [账号与项目管理](ACCOUNTS.md)。

## 技术实现

- React + TypeScript 前端，FastAPI + SQLAlchemy 后端，采用模块化单体和统一领域模型。
- 本地运行使用 SQLite 与本地后台队列；Compose 配置提供 PostgreSQL、Redis、Celery、API 与 Web 服务。运行依赖需按 [README](../README.md) 安装，源码不包含已安装环境和数据库。
- 默认配置中，视觉理解为 `qwen3.8-max`，全片文字审阅为 `qwen-plus`，视频生成为 `happyhorse-1.1-i2v`；真实调用需要自行配置可用的百炼接口、密钥及模型权限。
- VLM 接收带源时间的采样帧；提示词区分后期字幕、场景文字与可见实体动作。ASR 独立配置；未配置或失败时保留音频未分析状态，不据此断言对白或音乐缺失。
- 视觉请求默认最多 8 路并发，FFmpeg 默认同时 2 个任务、每个最多 4 线程；配额在同一部署内共享。视频生成独立限流为 1。模型响应等待默认 900 秒，可配置为 0；详见 [并发设计](CONCURRENCY.md)。
- 无影石 SDK 集成；当前直接导入普通视频文件，不依赖设备私有接口。

## 数据保护与可靠性

- 服务端 UUID 文件路径、FFprobe 实际格式检查、上传数量/时长/大小限制，原始视频保留。文件与预览请求受账号鉴权保护。
- FFmpeg 使用参数数组，不执行模型生成命令；媒体协议限制为本地文件与管道。
- 模型输出经过 Pydantic、引用归属与时间边界校验；只在约束内有限修复，仍不合法则明确失败。前端使用 React 文本渲染，面向用户的时间显示最多一位小数，内部时间精度保留。
- 上传、分析、补全提交支持幂等键。作业状态持久化，SSE 返回阶段和真实完成数量；全局进度与错误置于“任务与消息”浮层。
- 分析快照绑定主片、项目 revision 和配置。缓存按项目、素材及模型/提示词/采样配置隔离；迟到结果不覆盖新分析。
- 补拍复核沿用原任务条件，可使用升级后的真实模型重新分析新片段；主片或创作目标变化、新分析替代旧任务、演示与真实模式切换时仍拒绝过期或混用结果。AI 生成另行要求原分析配置与当前配置一致。
- `.env`、媒体、数据库、虚拟环境和前端构建目录不进入 Git。提交包不包含团队密钥、生产账号或用户项目数据。

## 验证与边界

已有本地自动化回归及真实模型样例记录见 [验证记录](VERIFICATION.md)。固定演示与 HTTP 模拟只验证程序规则，不能证明真实视频理解质量；真实样例也不能推广为准确率或通用性能结论。

当前重点仍是提供可追溯的建议和候选素材。镜头边界、动作理解、补拍可行性及前后衔接都需要人工检查；未来可补充人工标注评测、多浏览器验收、手动修正证据与镜头边界等能力。
