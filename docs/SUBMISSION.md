## 1. 源码包包含什么

源码包包含前后端代码、依赖清单与锁文件、数据库迁移、测试、配置模板、开发脚本和技术文档。提交 ZIP 仅包含从远程 `main` 全新 clone 后的 Git 跟踪文件，以 `赛道一_NJU人型token队_叙光集` 为顶层目录；不打包 `.git` 历史、已安装依赖、模型密钥、真实用户数据库、上传视频、AI 生成结果、服务器 SSH 私钥或预置用户密码。

因此，解压后应先安装运行依赖，再创建自己的账号和项目。**不附带依赖目录不等于零依赖或离线即用。** 安装需要访问软件包源；真实模型功能还需要自己的模型服务账号、相应权限与额度。

目录可以保留参赛名称，代码中的数据库、服务、Python/前端工程命名继续沿用 `xuguangji`，无需全局替换这些内部标识。参赛报告、介绍视频等非代码材料单独提交，不作为应用运行依赖。

## 2. 安装与启动

运行环境：macOS 或 Linux、uv、Python 3.12、Node.js 22.12+ 和 npm、FFmpeg 与 ffprobe。推荐使用 Node.js 24，以便直接执行附带的 TypeScript 前端测试。Windows 原生环境未验收。

在解压或 clone 得到的目录中打开终端，例如：

```bash
cd '赛道一_NJU人型token队_叙光集'
```

### macOS

安装 uv、Node.js 和 FFmpeg 后执行：

```bash
bash scripts/setup.sh
bash scripts/dev.sh
```

### Linux

当前 `setup.sh` 使用通用开发锁文件；Linux 请按以下步骤使用专用锁文件，避免缺少平台依赖：

```bash
uv venv --python 3.12 .venv
uv pip sync backend/requirements-linux.lock --python .venv/bin/python
test -f .env || cp .env.example .env
PYTHONPATH=backend .venv/bin/alembic -c backend/alembic.ini upgrade head
npm --prefix frontend ci
bash scripts/dev.sh
```

访问 <http://127.0.0.1:5173>。API 文档：<http://127.0.0.1:8000/docs>。前端将 `/api` 请求代理到本地 API；无需修改前端代码中的地址。两端口需要空闲，`Ctrl+C` 可停止服务。

默认数据库为 `data/xuguangji.db`，媒体也保存在 `data/`；首次运行无需外部数据库、Redis 或其他后台服务。`data/` 和 `.env` 均不提交到 Git。重新安装依赖前请保留自己的 `.env` 和 `data/`，安装脚本不会覆盖已有 `.env`。

## 3. 账号与项目

首次访问在登录页注册账号，无默认管理员口令。用户名为 3–32 位字母、数字、下划线或短横线，忽略大小写；密码长度为 8–128 位。用户只能查看自己的项目、素材、分析结果、任务及生成历史。

项目支持新建、搜索、重命名和删除。删除需要确认，正在处理的项目需先等待任务结束；当前采用软删除，不保证释放磁盘。全新源码包不会包含线上“杭州旅游vlog”等已有项目，评审可上传自有测试视频或使用固定演示案例。

如需升级自有旧数据库，应先备份并参考 [账号迁移说明](ACCOUNTS.md)；普通全新安装无需执行旧项目归属迁移命令。

## 4. 两种体验方式

### 4.1 无模型密钥：固定演示与媒体处理

保持模板中的 `MODEL_PROVIDER=mock`，注册后可使用首页“体验演示项目”或其他场景按钮。演示素材在本地由程序生成，语义结果来自固定标注；仅用于验证界面、状态与业务流程。

也可以上传普通 Vlog，检查文件校验、转码、镜头切分与片段回放。该模式不会真正识别普通视频的叙事内容，也不会调用真实 AI 视频生成。即使模板中 `VIDEO_GENERATION_ENABLED=true`，mock 模式下仍会拦截真实生成请求。

### 4.2 配置模型：实际视频分析与候选生成

编辑本地 `.env`：

```dotenv
MODEL_PROVIDER=qwen
MODEL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
MODEL_API_KEY=填入你自己的密钥
VLM_MODEL=qwen3.8-max
LLM_MODEL=qwen-plus
VIDEO_GENERATION_ENABLED=true
VIDEO_GENERATION_MODEL=happyhorse-1.1-i2v
VIDEO_GENERATION_BASE_URL=
```

上面的地址为配置示例。使用专属业务空间时，按控制台替换完整地址，并确认模型权限、地域与额度匹配。`VIDEO_GENERATION_BASE_URL` 留空时由兼容接口地址推导为同空间 `/api/v1`；需要单独配置时应使用百炼 HTTPS `/api/v1` 地址。修改环境后重启服务。

推荐按以下顺序体验：

1. 新建项目，上传一条已剪好的 Vlog，等待预处理完成。
2. 发起分析，回看建议所引用的时间段，确认真正需要采用的建议。
3. 生成补拍与重剪清单，阅读动作、景别、时长、插入位置和验收条件。
4. 在补拍任务中上传补充片段并分析；或者展开 AI 生成面板，选择参考首帧，修改描述与生成参数后提交。
5. 预览 AI 候选并提交复核，按逐项结果决定是否下载、重做或实拍补充。
6. 在其他剪辑软件中完成重剪、插入素材与成片输出。

AI 生成功能使用真实百炼额度，支持 3–15 秒候选片段。生成按钮可用还要求：任务属于已确认的补拍/生成类型、主片与创作目标仍匹配、有可追溯参考帧、当前配置与分析一致、项目容量足够，且没有尚未确认的上次提交。重剪任务只提供建议，不调用生成。

分析会向所配置的模型服务发送采样画面与相关文本；视频生成会发送参考首帧和提示词。没有模型账号或额度时可完整检查代码及固定演示流程，但不能据此声称已复现真实模型效果。

## 5. 验证方法

在依赖安装完成的源码根目录执行：

```bash
bash scripts/check.sh
node --test frontend/tests/verification.test.ts
```

第一条运行后端测试和前端 TypeScript/生产构建；第二条用 Node.js 24 运行补拍复核状态的前端测试。测试采用临时数据库、合成媒体及模拟模型响应，不使用线上项目或付费模型请求。

建议人工检查：注册/登录；两个账号各自创建项目后的隔离；上传与镜头回放；意见确认与忽略；清单生成；上传补拍片段后的结果状态；项目重命名和删除。真实模型与视频生成测试需另行配置服务，记录模型、输入、运行时间和实际结论，不能用固定夹具代替。

源码附带 [历史验证记录](VERIFICATION.md)，可用于了解开发过程；其中旧剪辑导出、旧模型、免登录共享等记载属于对应历史版本。当前功能与安装入口以 [README](../README.md) 和本文件为准。

## 6. 已知限制与常见问题

|情况|说明或处理方法|
|---|---|
|没有视频分析结论|先检查是否仍为 `MODEL_PROVIDER=mock`；真实分析需配置自己的模型服务并重启。|
|AI 生成按钮不可用|检查真实模型配置、权限和额度、补拍建议是否确认、参考首帧及任务是否有效；重剪任务不支持生成。|
|需要重新分析|更换主片、修改创作需求或已有更新分析后，使用匹配的新分析与清单。新建 AI 生成任务要求原模型配置一致；补拍复核可用当前模型重新理解片段，单纯真实模型或提示词升级不必重建原任务。|
|看不到已有线上项目|源码包不含线上数据库和视频；全新安装创建自己的项目，不连接现有生产服务。|
|音频未分析|默认未配置 ASR。提取音轨不等于理解对白或音乐；可配置返回时间戳 `segments` 的兼容识别服务，真实 ASR 尚未验收。|
|生成成功但复核不通过|生成完成与内容符合要求是不同结果；候选不会自动插入原片，需人工审看。|
|视频上传超限|默认单文件 256 MB、每项目 20 个素材、累计 600 秒，生成结果也占用项目容量。|
|专有相机格式不可用|先导出普通视角 MP4 等通用格式；未直接解析 INSV/INSP，未接入影石 SDK。|
|运行在 Docker 中|提供 Compose 配置作为可选路径，但未完成容器实机验收；首次评审优先使用本地运行流程。|

模型可能误读字幕、遗漏动作或给出缺乏依据的建议；镜头边界和时间定位也需回看核实。系统尚未建立实拍标注评测集，不宣称识别准确率、自动修复完整性或最终剪辑质量。单首帧生成不能保证与下一镜头连续，AI 画面也不能证明真实事件发生。

当前账号系统提供基础隔离，没有邮箱找回或企业级角色权限；多实例部署需要进一步完善共享限流、文件存储与任务恢复。仓库包含部署参考文件，但评审运行源码无需更改任何现有服务器。
