# HappyHorse 视频生成

视频生成功能由 `experiment/happyhorse-completion` 合入 `main`，与 Vlog 审看、补拍清单和验收功能共存。主分支保留黑黄主题、固定工作区、0.5 秒最短镜头和 900 秒模型读取等待；视觉理解使用 `qwen3.8-max`，全片文字审阅仍使用 `qwen-plus`。

## 处理流程

1. 上传一条已经剪辑好的 Vlog，检测转场并抽取每个镜头的关键帧，最多 8 路并发理解。
2. 对具体缺口生成补拍建议、插入位置与验收条件；先确认建议是否符合创作意图。
3. 在补拍任务中展开 AI 生成面板。系统根据建议准备提示词，选择一张原片参考帧作为首帧；可修改提示词、时长和分辨率。
4. 点击生成后创建后台作业，提交给 `happyhorse-1.1-i2v`。页面显示排队和生成进度，刷新后可恢复记录。
5. 成功后下载并持久保存 MP4，预处理为标记了 AI 来源的新素材；支持预览和下载。再提交现有验收流程检查是否符合原建议。

生成成功只表示得到片段。它不等于通过验收，也不会自动修改原片、替换时间线或宣称缺口已经解决。生成的内容属于创作补充，不能作为真实到访地点、发生事件或拍摄事实的证明。

当前产品不提供剪辑、成片版本管理或成片导出。生成结果的“下载片段”保留，供用户在其他剪辑软件中使用；实拍补充视频仍可上传并按建议逐项分析。

## 模型边界

HappyHorse I2V 只接收一张首帧，不接受末帧，因此不能保证与后一个镜头无缝衔接。支持 3–15 秒、480P/720P/1080P，默认时长参考补拍建议并限定在该范围，默认清晰度为 720P，并开启模型水印。首帧两边需至少 300 像素，宽高比 0.4–2.5，图像不超过 20MB。系统从有来源记录的任务参考帧选择图片，不接收任意外部文件路径。

理解并发与生成并发独立：视频理解保留 8 路，生成默认同时 1 个。模型通常需要几分钟生成；任务 ID 和云端结果链接有效期约 24 小时，应用成功后保存本地副本。

每次点击生成都会使用视频生成额度，实际价格和消耗以账户额度和账单为准。

## 可靠性

- 同一请求使用幂等键；提交前记录提交状态，收到云端任务 ID 后立即保存。
- 后续失败重试优先恢复已有云端任务的查询和下载。提交网络超时且没有收到任务 ID 时，不自动重新提交，避免重复计费。
- AI 生成要求原分析配置与当前配置一致，模型/采样配置变化时需要重新分析并生成任务。补拍复核则可以沿用原任务条件，由当前模型重新理解新片段；主片、创作目标或需求变化、更新分析替代旧任务、演示与真实模式混用时仍会阻止旧任务。
- 密钥只保存在服务端环境文件。生成媒体的下载请求不携带模型密钥；生成记录与素材保留来源关系。
- 生成前为请求时长额外预留 0.5 秒空间，兼容已实测的 5 秒请求返回 5.125 秒视频；素材入库按实际时长计算，不重复增加余量。默认提示词与参考图说明使用原片时间段，原始任务和验收条件保持不变。

## 使用环境

在主分支服务端环境配置 `VIDEO_GENERATION_ENABLED=true`、`VIDEO_GENERATION_MODEL=happyhorse-1.1-i2v`，沿用已有百炼业务空间密钥。`VIDEO_GENERATION_BASE_URL` 留空时由 `MODEL_BASE_URL` 推导同一业务空间的 `/api/v1` 地址。生成并发默认 1，轮询间隔 15 秒，一轮查询等待 900 秒；超时可用原云端任务 ID 恢复，不再次付费提交。无需新增数据库表、迁移或独立服务，现有 worker 同时处理生成任务。

本地也可先执行 `npm --prefix frontend run build`，再在仓库根目录运行 `.venv/bin/python scripts/preview_happyhorse.py --port 8002`，通过 `http://127.0.0.1:8002` 同时访问网页和 API。首次使用仍需按 [README](../README.md) 安装依赖、配置环境并执行数据库迁移；打开网页后注册或登录自己的账号。此启动器仅监听本机，要求 `QUEUE_MODE=local`，读取当前环境中的数据库与数据目录配置，不会自动创建隔离副本；如需与其他实例同时运行，应先配置独立的 `DATABASE_URL` 和 `DATA_DIR` 并执行迁移。

当前版本需要账号登录，生成任务与媒体均按项目所属用户隔离。对于切分或模型配置已变化的旧项目，发起新的 AI 生成前需重新分析、确认所需补拍建议，再生成新的补拍清单；旧清单不会绕过生成配置与来源校验。已生成的片段仍需人工审看和验收，不自动插入原片。

- 复制已有杭州 Vlog 到独立实验数据库，原线上项目不变。96 秒视频切出 28 个镜头，使用 `qwen3.8-max` 重新理解，再由文字审阅生成 5 条建议。
- 选取“香积寺到河岸缺少过渡”的建议，在实验副本中确认后提交一次 5 秒、720P 的 `happyhorse-1.1-i2v` 请求。同一幂等键重复请求返回相同 Job，未创建第二次云端生成。
- 云端生成、下载、入素材库与预处理均成功。输出为 1280×720、有音频 MP4，容器时长 5.125 秒，约 7.9MB；本地保存于 `data/smoke/happyhorse-completion-5s.mp4`（不纳入 Git）。原片参考为祈福牌架与白墙，生成镜头向右移动，出现院门和单车。
- FFmpeg 可完整解码，媒体 Range 请求返回 206；查看首、中、末采样帧，观察到环境与光线延续。这是单个真实样本，不代表生成质量或连续性已普遍验证。

- 首次验收出现引用原片证据 ID 的问题，实验分支新增一次有边界的语义修复：只接受新素材证据、原验收条件不变，二次仍不合法则显式失败。重试后得到上述有效验收结论，没有放宽验收来制造通过结果。
