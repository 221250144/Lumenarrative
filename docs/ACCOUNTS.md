# 账号与项目管理

全新克隆或解压源码后，按 [本地启动说明](../README.md) 初始化数据库，再在网页注册自己的账号。源码包不附带线上账号、密码或用户项目；不需要执行下面的旧数据归属操作。

提供用户名和密码注册、登录、退出及修改密码。账号为 3–32 位字母、数字、下划线或短横线，忽略大小写；密码为 8–128 位。每个用户只能访问自己创建的项目及其素材、分析、补拍任务、生成历史和进度事件。

项目卡片提供重命名与删除。仅改名不会使分析过期。删除需要确认；有排队或执行中任务时返回 409，等待完成后再删除。当前使用软删除：项目和相关入口立即不可访问，底层记录与素材保留用于运维恢复，不承诺释放磁盘空间。

## 升级旧数据

先备份数据库，再运行 Alembic。`0002` 新增用户、会话表以及项目的归属、删除标记。旧项目初始 `owner_id=NULL`，对所有网页用户隐藏；不会将它们自动送给第一个注册者。

在项目目录、服务端环境变量已加载的情况下，执行以下命令创建负责人账号并分配所有尚无归属的旧项目。命令交互读取密码，不在参数中传递或打印密码。

```bash
PYTHONPATH=backend .venv/bin/alembic -c backend/alembic.ini upgrade head
PYTHONPATH=backend .venv/bin/python -m app.manage_users caozheng --claim-legacy
```

服务器使用 `/opt/xuguangji/venv/bin/python` 替换 `.venv/bin/python`。自动化部署可使用 `--password-stdin`；仅有明确重置需求时使用 `--reset-password`，重置会注销该账号全部会话。已有归属的项目不受 `--claim-legacy` 影响。

本次新增表与字段对旧代码读取兼容，但回退到免登录版本会重新开放原有项目访问，因此不能仅回退网页代码来恢复服务。迁移不提供自动 downgrade；有需要时恢复迁移前备份并核对数据。

## 实现约定

- 密码使用带随机盐的 PBKDF2-HMAC-SHA256，600,000 轮；数据库不保存明文密码。
- 登录凭据为随机会话 Cookie，数据库仅保存其 SHA-256 摘要和到期时间。Cookie 为 HttpOnly、SameSite=Lax，默认有效 14 天。当前 HTTP 部署 `AUTH_COOKIE_SECURE=false`，使用 HTTPS 时改为 `true`。
- 退出删除当前会话；修改密码撤销全部旧会话，并为当前浏览器签发新会话。
- 写 API 需要 `X-Requested-With: XMLHttpRequest`，前端统一发送该头，阻止外站表单借用 Cookie 提交操作。健康检查和素材来源能力查询保持公开。
- 登录、注册及改密采用进程内按来源限速；当前单 API 进程生效。未来多 API 实例需改为共享限速存储。
- 访问别人的项目及其子对象返回 404；未登录返回 401。项目写入与删除由项目行锁协调，素材上传及生成在提交前重新校验归属。
- SSE 在持续推送时重新检查会话与项目可见性。前端退出或切换账号会清空工作区并中止旧请求及事件流。
- 所有业务响应和媒体设置 `Cache-Control: private, no-store`。原片、预览、缩略图和参考帧均经过后端鉴权，没有静态文件旁路。

## 检查

`backend/tests/test_accounts.py` 覆盖不同账号的项目、媒体、分析、任务和生成接口隔离，删除、改名、退出、改密、会话过期及请求头校验。`test_accounts_migration.py` 使用旧结构数据库验证迁移不丢失原项目和作业，再验证显式归属迁移。
