# 8 核服务器并发设计

当前单机使用 8 路镜头分析、全服务器共享 8 个模型调用名额。百炼在云端执行推理，本机多核负责视频处理；模型并发主要减少等待网络响应的串行时间。

## 执行方式

同一 Vlog 的分析窗口进入 `ThreadPoolExecutor`，最多 8 个同时请求视觉模型。各线程只拿不可变素材快照和时间范围，不共享 SQLAlchemy Session，也不写数据库。调用线程按已完成窗口数更新进度；全部完成后按原片顺序合并，单窗口失败只记录该窗口，不丢弃其它成功结果。全片总结仍在视觉结果汇总后调用一次。

进程内线程池不是服务器总限额。`resource_slot()` 使用同一 `DATA_DIR` 下的 POSIX 文件锁，让所有 Celery 进程、API 及线程共享模型和媒体配额。正常返回、异常或进程退出都会释放锁；不删除活动锁文件。这个机制要求单机共享本地文件系统；未来多机部署需改用分布式限流。

|设置|当前值|含义|
|---|---:|---|
|`WORKER_CONCURRENCY`|8|Celery 同时调度 8 个后台任务|
|`MODEL_CONCURRENCY`|8|每片最多 8 个分析线程；整台服务器最多 8 个模型调用|
|`MEDIA_CONCURRENCY`|2|最多两条重型 FFmpeg 命令同时运行|
|`FFMPEG_THREADS`|4|每条命令的输入解码、输出编码和滤镜线程预算|
|systemd `CPUQuota`|800%|worker 及其视频处理子进程合计最多使用 8 核 CPU|
|`DB_POOL_SIZE` / `DB_MAX_OVERFLOW`|2 / 2|每个 PostgreSQL 客户进程最多 4 个连接|
|`MODEL_TIMEOUT_S`|180|为较慢的全片结构化总结预留时间|

FFprobe 元信息读取不占重型媒体名额。同一素材的完整预处理另有独占锁，避免两次分析同时升级旧分镜时覆盖同一个预览文件；不同素材仍可并行处理。

本地 SQLite 模式保留单后台任务调度，每个任务内部支持并行理解镜头。生产环境使用 PostgreSQL、Redis、Celery。Compose 已同步参数，但当前正式部署采用 systemd。

## 速度与验证

升级前最近一次实际分析耗时 447.516 秒，其中 71 次视觉调用累计 363.29 秒（中位数 4.86 秒），一次全片文本总结 83.81 秒。主要瓶颈是串行等待视觉模型，并发无法消除最后一次总结、转码和上传时间。

自动化测试验证了：8 路实际线程重叠、跨进程共享配额、异常和进程退出后释放、窗口乱序完成但结果保持原顺序、单窗口原子失败、完整缓存复用，以及真实 FFmpeg 分镜和渲染。16 窗口、每窗固定模拟网络延迟 40ms 的一次测试为串行 0.7026 秒、8 路 0.0890 秒；这是模拟测试，不能作为百炼真实速度承诺。

服务器实测同一段 8 镜头合成视频，两轮均实际调用 `qwen3-vl-plus`，没有使用应用证据缓存：

|视觉提取方式|耗时|实际 HTTP 请求峰值|请求数|失败窗口|
|---|---:|---:|---:|---:|
|串行 1 路|32.324 秒|1|8|0|
|并行 8 路|5.340 秒|8|8|0|

本次视觉阶段约提速 **6.05 倍**。该对照不含上传、转码与最后一次全片总结，也不代表所有 Vlog 都会得到同样倍率；百炼服务端缓存和瞬时负载未被控制。测试使用独立数据库，不修改用户实际项目。

并发不会减少需要理解的镜头数量。实际速度还受百炼延迟、RPM/TPM 限流、窗口数量和重试影响；保留现有 429/暂时错误退避与重试。百炼按账号和模型限流，参见[官方限流说明](https://help.aliyun.com/zh/model-studio/rate-limit)。调整配额后须让所有进程使用一致配置并重启；运行中的任务应先完成。

全片审阅增加一次定向引用修复：若结构合法但锚点/证据引用不合法，把原结果与具体错误反馈给模型重新回答；第二次仍不合法就明确失败。不会静默删除非法引用或把错配结果当成有效诊断。视觉事实缓存仍可复用。

## 模型选择（2026-09-22 核实）

当前部署继续使用 `qwen3-vl-plus` 做视觉观察、`qwen-plus` 做全片审阅。本次优化并发调度，没有同时更换模型，以便独立评估速度变化。

百炼官方把 `qwen3.8-max` 列为高能力旗舰，支持图像、视频和结构化输出；`qwen3.7-plus` 为能力与成本均衡选择，`qwen3.8-flash` 为轻量低成本选择。参见[视觉模型](https://help.aliyun.com/zh/model-studio/vision-model)和[文本模型](https://help.aliyun.com/zh/model-studio/text-generation-model)。当前业务空间的 `/models` 列表包含这些 ID；列出模型不等于已经完成该账号的推理兼容和效果验收。

针对本产品，可以对比“`qwen3.7-plus` 逐镜头理解 + `qwen3.8-max` 全片审阅”。这是待实拍 Vlog 对比验证的升级方案，尚未切换生产配置，也不据官方通用能力档位宣称本项目准确率已提高。
